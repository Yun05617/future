# 問題紀錄

更新日期：2026-10-03（Asia/Taipei）。依使用者最新指示，下修身分辨識門檻並加入肖像淡入；語音合成及嘴型同步仍待討論，不在本次變更範圍。

## 新版預覽錄音：服務無權限保存錄音

狀態：原因已確認；已加入介面錯誤處理，正式啟動後待驗證。

- 代理程式開啟的 `7863` 版面預覽使用受限帳號執行，使用者送出錄音後，`workspace.archive_input` 在 `shutil.copy2` 保存錄音時發生 `PermissionError`。
- 不是人物圖載入失敗，也不是聲紋相似度門檻問題；此次錄音尚未送進分析模型。
- `_run_turn` 已補上此權限錯誤的處理：顯示明確訊息、保留既有對話與錄音輸入，不再讓所有輸出元件直接顯示例外。
- 正式使用應從檔案總管以使用者 Windows 帳號啟動 `../啟動全部_Windows.bat`，並使用 `http://127.0.0.1:7862/`。該啟動方式會載入已加入肖像的最新版程式。
- 此錯誤處理不等於修復作業系統存取權限；正式服務仍需實際測試。`7863` 受限預覽不應用來驗證錄音保存或 Windows 語音播放。

## 身分辨識：已登錄成員仍顯示未知使用者

狀態：已實作暫時方案，正式服務重新啟動後待實測。依使用者指示，選取最高相似度且嚴格大於 `0.40` 的成員；取消原本 `0.03` 的第一、二名差距限制。剛好 `0.40` 或沒有可用範本仍是未知使用者。辨識結果、各成員分數與錄音連結保存於既有分析紀錄，成功對話也會記錄成員身分；不自動追加訓練樣本。降低門檻可能增加誤認，仍非身分認證機制。原問題證據見 [身分辨識問題紀錄](2026-10-03-speaker-identity-issue.md)。

## 人物肖像：正式頁缺圖與等待回覆時淡入

- 檢查時正式 `7862` 的 `/config` 沒有 `companion-header` 元件，代表執行的是尚未加入肖像的舊版；須以正常 Windows 啟動檔重啟，不能僅重新整理瀏覽器。
- 最新程式初始隱藏人物，但預先載入原圖並保留畫框位置。錄音／上傳音訊送出後，讓畫框捲入可視範圍，等待回覆的前 2 秒由透明淡入，完成後保留顯示。
- 依最新需求，文字輸入不會啟動首次肖像淡入；首次音訊送出後，肖像持續顯示。重新錄音、新增／清除／切換對話或錯誤都不隱藏、不重播動畫；重新整理頁面才重置。
- 這是靜態肖像淡入，不是嘴型動畫，不會為動畫而延後後端回覆。
- 最新外觀依使用者參考照片調整五官，改為透明背景人物。已移除畫框、底色與陰影，下緣柔和淡出；首次淡入後持續顯示的邏輯不變。

## 對話回覆：否定身分辨識功能，以及第一次未辨識

狀態：提示詞與首次成功辨識的稱呼邏輯已修改，正式服務重啟後待驗證。

- 使用者最近同一對話的錄音 `79b5968d18014406b3d39bebb0035f5c` 相似度 `0.5495`，判定未知；下一段 `6a0d468f6ae04076a9bd09a60b607f36` 相似度 `0.6794`，判定姜昀廷。兩者皆以姜昀廷為最高候選。
- 當時正式頁的 `/config` 仍缺少新版肖像與淡入元件，且第一段 `0.5495` 被拒絕與舊 `0.62` 門檻一致；新版 `> 0.40` 規則應讓兩段皆通過。不能把差異解釋為必須先聽第二次才能辨識。
- 舊提示詞要求將身分稱為「推測」、不可當成事實，造成模型主動否認身分辨識功能。新版要求依系統聲紋結果直接稱呼已辨識成員，不主動加上能力否認；未知時不猜名字，主動問技術／準確度時仍如實說明限制，不保證百分之百正確。
- 同一對話先未知、後首次辨識成功時，也會加上姓名問候，不再只在對話第一回合加姓名。
- 每段對話的每位成員只加一次全名問候；即使中途未知或換人，再辨識到同一人也不重複全名。提示詞要求一般後續對話使用「你」，明確詢問身分／姓名時仍可回答全名。
