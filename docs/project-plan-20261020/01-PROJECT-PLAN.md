# 具身分辨識與情緒感知的聊天機器人專案計畫書

版本 1.0｜2026 年 10 月 20 日｜四週開發與內部驗證計畫

## 計畫摘要

本專題以多人家庭共用的日常陪伴為首要情境。使用者可透過語音聊天，系統辨識說話者、分析聲音情緒、轉寫繁體中文，並在本人確認身分及通過 PIN 後，讀取該成員的聊天脈絡與已同意保存的長期記憶。本機語言模型產生回答，再合成語音。使用者亦可上傳自己有權使用的照片，以完整語音回答生成同步嘴型、表情及頭部動作的人像影片。

人臉身分與情緒辨識為使用者可選擇開啟的輔助功能；現有 Google Teachable Machine 模組維持獨立展示，聲音與影像融合列入後續版本。從影片擷取音訊並形成個人回覆音色，列入第二階段研究，不是四週第一版的完成承諾。

本計畫分兩條開發線並行：A 線由使用者負責照片說話；B 線由另一位開發者負責核心語音、身分、情緒及 PIN。記憶與前台整合暫由 B 線主責、A 線協作，第一天確認工作量。另兩位組員分別負責資料測試與跨平台整合測試。總投入以每週約 20–40 人時、四週約 80–160 人時估算；新增影片生成後，時程必須在第一週技術驗證後重新檢查。

## 二 功能範圍與非目標

第一版包含語音與文字輸入、四位已登錄成員聲紋候選、PIN、三類情緒、語音回覆、完整人像影片工作、歷史搜尋刪除，以及結束對話時勾選保存的長期記憶。保留簡單瀏覽器動畫作為載入提示或失敗降級，但不得將其標為自然說話影片已完成。

第一版不包含即時串流人像、多人同時發言分離、醫療診斷、已證明的家庭陪伴療效，以及已通過驗證的陌生人拒識。未登錄訪客本輪不測，必須在成果中揭露此限制。PIN 降低應用程式內的誤用，並不等於資料庫已加密，也不能保護擁有本機檔案存取權的其他作業系統帳號。

以下流程屬已確認需求；閒置秒數、PIN 長度與重設流程、照片品質評分、影片長度測試上限屬建議預設，需第一週確認，不偷偷當成既定成果。

## 三 互動流程

### 3.1 成員開始使用

開啟展示頁後保持鎖定，畫面只顯示公共歡迎內容，不顯示上一位成員的姓名、紀錄、照片或待確認記憶。使用者錄音後取得候選身分，先問是否為本人；本人確認後輸入 PIN。伺服器核對通過才載入成員記憶。文字輸入也需通過相同登入流程；文字不能自動證明說話者身分。

聲紋是候選判斷，不是登入憑證。更換候選姓名、重新整理頁面、修改前端參數或呼叫資料接口，均不能跳過 PIN。禁止將聲紋相似度呈現成準確率。

### 3.2 對話中換人與低信心

每段新錄音有獨立 request_id、雜湊及音檔路徑，禁止重送前一輪錄音或轉寫結果。身分相符且會話未過期時，才可使用該成員資料；若候選變成另一人，先撤銷目前授權並清空畫面，再確認新身分及 PIN。

若聲紋信心不足，撤銷原授權並進入訪客對話，不讀取或寫入任一成員記憶。訪客內容暫存在記憶體，只供當次回覆；不生成長期記憶候選。再次變成成員時需重新確認及解鎖。低信心時不能沿用上一個人的個人化照片或已產生的私人影片。

閒置鎖定時間建議先設 5 分鐘並可設定，第一週決定。任何鎖定均使在途請求失效，停止播放並隱藏紀錄；背景生成晚到的結果不得重新出現在下一位使用者的畫面。

### 3.3 情緒與本人陳述

聲音分類為正面、負面、平靜；語意則來自本次有效轉寫。只有明顯正面與負面相反時，以自然且不暗示答案的方式問本人感受，例如「你剛才提到很難過，現在比較接近什麼感受？」確認之前可先回應事件本身，不能武斷說本人情緒錯誤。平靜與其他分類不同時不因此追問。

顯示聲音模型估計與本人確認感受為兩個欄位。確認的感受只影響當輪或明確範圍，不自動變成永久人格標籤。人像表情主要呈現助理回應語氣，不因負面情緒就生成誇張悲傷表情；此互動規則列為品質評審項目。

### 3.4 記憶保存與刪除

聊天紀錄與長期記憶分開保存。模型只能提出記憶候選，沒有直接寫入權。按結束對話後顯示可編輯、可勾選清單，經本人確認才保存；拒選不影響既有聊天紀錄。先鎖定的候選留在本機，但只有同一成員重新通過 PIN 後才能看到。

每筆記憶紀錄 owner_id、source_conversation_id、source_message_ids、confirmed_at 與版本，保留修改及撤銷關聯。刪除對話時先查相關記憶，預設連同刪除；使用者可明確保留。記憶若彙整多段對話，顯示其他來源與影響範圍，不因來源刪除而悄悄消失或洩漏其他使用者資料。

保留記憶而刪除原文時，以最少必要來源 ID 保存稽核關聯，不保存被刪原文副本。刪除需連動搜尋索引、候選記憶、衍生摘要與可辨識的影音工作；快取及備份保存政策須在界面說明。預設私人備份不由程式自動上傳 GitHub。

## 四 照片說話的明確定義

照片中的人物是助理呈現形象，可能和登入成員不同；上傳照片不能用來自動登錄或解鎖聲紋身分。使用者可選擇預設形象、自己的照片或取得同意的照片，並可刪除。明確標示合成內容，不宣稱照片中的真人正在即時回覆。

工作輸入為可用的單人照片、當輪完整回答音訊、表情提示與輸出規格。產出為單支可在瀏覽器播放且附原回答音軌的影片，嘴型須對準實際音訊，並包含自然表情與頭部動作。單純音量驅動張嘴、靜態圖加聲音、眨眼循環，不算本項通過。

人物照片沿用開發版既有建議：JPG、PNG、WebP，單人正面、光線清楚；10 MB 與最長邊 4096 像素為待同步到遠端的驗證限制。檢查解碼、EXIF方向、過大像素、多人、無臉與非照片內容。未通過者提示重選，不讓檔案格式錯誤拖垮服務。

### 4.1 完整回答與等待上限

人像模式等完整影片完成才播放，保留較長內容，不拆分成多段。30 秒從結束錄音起算，包含授權後的聲音分析、轉寫、語言模型、TTS、排程、渲染與影片就緒等待；若需要使用者輸入 PIN 或確認情緒，另記人工等待時間及端到端總時間，不把人工時間偷偷算成模型變快。

30 秒為目標，不是已測結果，也不是任意長度影片保證。第一週以相同照片及 10、20、30 秒完整回答音檔做長度分層，兩平台各測冷啟動與暖機；更長回答另列超出目前驗收範圍，不以截斷回答假裝通過。長度上限最後由測試及使用者確認。

超過 30 秒仍無法開始播放時顯示選項：繼續等、改聽語音、取消。改聽語音後影片可在完成時標為可重播，但不得再自動重播聲音；取消後晚到結果丟棄。影片失敗不清除文字答案，也不重做聊天或重複寫入歷史。

### 4.2 模型選型關卡

目前 LivePortrait 的主要工作是轉移 driving video 或動作資訊，不能只把新 TTS 音軌貼上去就宣稱嘴型同步。需驗證真正的 audio-to-motion 或 lip-sync 階段及人像表情生成。可抽換後端，不先把某個研究模型寫死在共用聊天環境。

來源、程式碼授權、模型權重授權、臉部偵測器與聲音模型均分開登錄。既有 LivePortrait 上游作者資訊含 Kuaishou；SadTalker 上游列出 Tencent 等機構。團隊先前提供的參賽切結書有來源限制，因此這些方案只能列待審核，不直接宣稱可用於競賽。Wav2Lip 可作非商業研究的嘴型基準，但有使用限制，且本身不等於自然頭部與表情系統。

第一週模型評選輸出必須包含：實際上游 commit、權重 SHA256、來源及使用範圍、中文同步、兩平台可啟動性、記憶體峰值、冷暖耗時及影片可播放性。若找不到同時合規且達標方案，保留語音版，將自然影片明確標為實驗；不因時程壓力改寫結果。若涉及競賽資格疑義，由團隊向主辦方取得確認。

## 五 系統架構與共同接口

兩位開發者共用一份主程式、兩種平台啟動方法，不各自維護一整套聊天系統。核心線產生標準音檔與工作資料；人像線只接收授權後最少必要素材，不直接查詢成員紀錄或 PIN。

建議拆為六個邏輯模組：Session/Auth、Audio Analysis、Conversation/Memory、Reply/TTS、Avatar Jobs、Presentation。先在既有 Python 模組增加邊界，除非相依環境真的衝突，不急著更換 Gradio 或拆成多個微服務。人像模型若與主程式 Python／Torch 版本不合，以獨立子行程或本機服務隔離。

主要資料流：錄音 → 候選身分及授權 → 當輪轉寫與情緒 → 成員隔離的歷史檢索 → LLM完整回答 → TTS音檔 → 人像工作 → 完整影片播放。已授權後，可平行執行無相依的聲音特徵分析與轉寫；不得在授權前取出私人記憶再交前端判斷。

完整欄位、錯誤狀態與取消語義見 03-INTEGRATION-CONTRACT.md。此文件中的 API 為目標契約，並非既有網址；未實作前不得將範例 curl 當作可用服務。

## 九 風險與決策觸發

第一大風險是完整長回答影片的30秒目標，尤其M3 16GB同時載入語音、LLM與人像模型時。第一週就測，紀錄各模型載入與卸載成本；必要時串行使用記憶體、預處理照片、調降輸出解析度，仍以自然度評審通過為限。不能把CUDA專用加速當作Mac也支援。

第二是兩份程式版本漂移。遠端來源與Mac檔案按功能比較，鎖定 requirements 的可安裝版本與來源 commit；新增模型環境不覆蓋主環境。第三是PIN及記憶越權，採伺服器權限檢查、session世代與可重現測試。第四是資料不足：四位開發相關人員並非一般家庭樣本，報告保留限制，未知訪客尚未測。

尚待第一週決策：PIN長度與重設流程、閒置秒數、輸出影片長度與解析度、模型來源資格、Windows CPU及RAM、個人音訊及影音快取保留天數、主要回覆模型。建議預設記在Issue，未確認不能成為已實作承諾。

## 十 第二階段影片音色與人臉融合

影片中的人像、影片中的聲音與登入成員是三個不同主體，不能用影片聲音訓練聲紋後就當成回覆音色。未來流程為本機擷取音軌、選定單一說話者且去除音樂或重疊聲、確認本人或授權、建立TTS參考音色、合成中文新回答，再將新音檔交給人像影片後端。這可能是參考音色推論，也可能需微調，依選定模型決定；不可先宣稱已完成音色訓練。

攝影機預設關閉，使用者同意後才開；關閉時立即停止影像取得。臉部身分與情緒結果可先獨立呈現，未驗證前不固定聲音／臉部各50%等權重，也不能跳過PIN。研究需另設資料與人像授權、模型資格、中文可懂度及相似度驗收。
