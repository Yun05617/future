# 身分辨識與情緒感知聊天機器人：語音模組設計

## 目標

擴充既有的本機三情緒語音 Demo，使它可在同一個介面中處理中文錄音或上傳音檔，並產生：

1. 說話者身分與信心分數。
2. 正面、負面、平靜三種情緒的分數與最終判斷。
3. 中文逐字稿、人工校正文字與轉寫品質紀錄。
4. 供本機 Ollama 聊天模型使用的整合分析結果。

系統的已知說話者是：莊媗丞、姜昀廷、紀律廷、趙科翰。未達身分判斷門檻的聲音顯示為「未知使用者」。所有音檔、標籤、模型與紀錄只留在本機。

## 架構決策

語音身分辨識、語音情緒辨識、語音轉文字採用獨立模組，最後由整合層組合結果。不要把三項任務訓練成單一分類器。

原因如下：

- 身分辨識需要穩定的聲紋特徵；情緒辨識需要語速、音高、能量等表達特徵。混合訓練會讓情緒改變造成身分誤判。
- 中文逐字稿是序列轉寫任務，和前三者的分類問題不同。
- 各模組可個別測試、校正與報告，整合時仍只需要一個網頁介面。

```text
錄音或上傳
    ↓
自動保存原檔 → 降噪與標準化（16 kHz、單聲道 WAV）
    ↓
 ┌───────────────┬────────────────┬────────────────┐
 │               │                │                │
 ▼               ▼                ▼                ▼
聲紋向量       情緒特徵           中文逐字稿       分析紀錄
ECAPA-TDNN      現有 XLS-R         Whisper
 │               │                │
 ▼               ▼                ▼
身分＋未知判定  情緒分數           原始文字／校正文字
 └───────────────┴────────────────┴────────────────┘
                         ↓
               Ollama 本機中文聊天回覆
```

## 模型與授權紀錄

| 任務 | 方案 | 使用方式 | 正式文件需記錄 |
|---|---|---|---|
| 情緒 | 現有 XLS-R 300M 特徵＋本機分類器 | 保留既有三情緒 Demo，依更正資料重新訓練 | 版本、資料量、Accuracy、Macro F1 |
| 身分 | SpeechBrain ECAPA-TDNN 聲紋嵌入 | 取得每人訓練錄音的向量平均值，與新錄音做餘弦相似度比對 | 模型版本、Apache-2.0、未知門檻 |
| 轉寫 | OpenAI Whisper | 固定語言為中文，在本機產生逐字稿 | 模型大小、MIT、字錯率統計 |
| 聊天 | Ollama 本機模型 | 將文字、身分與情緒傳入本機 API | 模型名稱、版本、授權、系統提示詞 |

正式參賽前需將確切權重版本、下載來源與授權寫入 `07_專題文件/模型來源與授權.md`，並再對照 InnoServe 當年度規章。不得以中國或中資機構開發、維護的模型或介接工具做訓練或推論。

## 身分辨識設計

### 訓練

每段乾淨的訓練音檔經過降噪與標準化後，轉換為 192 維聲紋向量。每位成員的所有向量取平均並正規化，形成一筆聲紋範本。這不是對 ECAPA-TDNN 重新微調；只會訓練和保存四位成員的本機範本，因此少量資料也能做出可展示的結果。

每位成員第一版至少蒐集 20 段，每段 4–8 秒。錄音內容必須多樣，包含一般陳述、問題句、不同音量與不同語速；避免每段只念相同句子。

### 推論與未知使用者

新音檔的聲紋向量與四筆範本分別計算餘弦相似度，最高者為候選身分。若最高分低於設定門檻，或第一名與第二名的分數差過小，結果改為「未知使用者」。

門檻不預設為固定數值。先以四位成員保留的測試錄音和組員以外朋友的錄音測試，選出降低陌生人誤認率的門檻，再寫入設定檔。介面顯示每位成員的相似度與最終結果。

使用者可更正誤判的身分。更正後，音檔會自動加入正確成員的訓練資料，重建該成員聲紋範本，並留下可撤回的更正紀錄。

## 中文轉寫與人工校正

Whisper 僅設定為中文轉寫。介面會呈現原始逐字稿、偵測時間與可編輯的「正確文字」欄位。

儲存校正時保留原始轉寫與校正文字，並以中文字元錯誤率（CER）計算每段與累積品質：

```text
CER = (替換字數 + 刪除字數 + 插入字數) / 校正後文字字數
```

第一階段的校正資料只作為品質證據與報告素材，不用於微調 Whisper。這避免少量資料造成模型品質下降與訓練時間增加。

## 自動保存、降噪與資料夾

資料根目錄固定為：`~/Desktop/專題研究`。每一次錄音或上傳後，系統在分析前就自動保存原始檔；即使使用者沒有按訓練或更正，也保留這筆資料。

```text
~/Desktop/專題研究/
├── 01_原始音檔/
│   ├── 自動留存/                   # 原始上傳／麥克風檔，依日期命名
│   ├── 身分辨識/莊媗丞/
│   ├── 身分辨識/姜昀廷/
│   ├── 身分辨識/紀律廷/
│   ├── 身分辨識/趙科翰/
│   └── 身分辨識/未知使用者測試/
├── 02_情緒辨識/
│   ├── 正面/
│   ├── 負面/
│   ├── 平靜/
│   └── 模型/
├── 03_語音身分辨識/
│   ├── 聲紋向量/                   # 每段音檔的 ECAPA 向量
│   ├── 成員聲紋範本/               # 四位成員的平均向量
│   ├── 未知門檻校準/               # 已知／未知測試結果與門檻
│   └── 模型/                       # 模型中繼資料與設定
├── 04_中文語音轉文字/
│   ├── 原始轉寫結果/               # Whisper 的 JSON 結果
│   ├── 人工校正結果/               # 原始文字、正確文字、CER
│   └── 正確率報告/                 # 累積 CER 與測試摘要
├── 05_完整分析紀錄/                 # 每段的身分、情緒、轉寫整合 JSON
├── 06_聊天整合/
│   ├── Ollama設定/
│   └── 對話紀錄/
```

原始檔不覆寫。處理過的 WAV、特徵、模型與 JSON 以 UUID 和時間戳命名，metadata 包含來源檔、說話者標籤、情緒標籤、處理版本和建立時間。更正與撤回只更新標籤及範本，不刪除原始檔。

降噪只用於模型輸入與處理後副本；原始音檔永遠保留。若降噪導致語音太短、靜音或損壞，頁面會拒絕用於訓練並保留原檔與失敗原因。

## 整合介面流程

1. 使用者錄音或上傳常見音訊格式；系統自動保存原檔。
2. 使用者可標註訓練用途：說話者、情緒、是否作為未知使用者測試。
3. 系統降噪與標準化後，自動存入相對應資料夾。
4. 點選訓練時，可分別更新情緒分類器與聲紋範本；介面顯示各自訓練狀態。
5. 點選分析時，頁面同時輸出身分分數、未知判定、情緒分數、中文逐字稿與處理時間。
6. 使用者可更正說話者、情緒與逐字稿；身分／情緒更正會更新其訓練資料，逐字稿更正只更新品質資料。
7. 點選「開始聊天」時，整合層將校正優先的文字、身分和情緒傳給 Ollama，並顯示文字回覆。

## 錄音句庫

每位成員錄製以下 20 段身分辨識句，每句錄一次；若時間允許，在不同時段再錄一次。句子可依自然說法微調，但不要全員照相同語速念。

1. 今天的天氣很適合出門散步。
2. 我正在準備畢業專題的展示內容。
3. 請幫我確認這份資料是否已經更新。
4. 我想知道這個功能目前是否可以使用。
5. 下午三點我們要一起討論研究進度。
6. 這段錄音用來測試說話者辨識功能。
7. 請把分析結果顯示在畫面上。
8. 我剛剛上傳了一個新的音訊檔。
9. 我們需要再確認一次模型的準確率。
10. 今天的工作進度比昨天順利一些。
11. 我希望系統可以辨識不同使用者的聲音。
12. 這個專題結合了身分辨識與情緒感知。
13. 請問目前有沒有需要修正的地方。
14. 我想把這段話轉換成正確的文字。
15. 這是一次本機端的語音測試。
16. 我們會把所有資料保留在自己的電腦。
17. 請幫我把這個功能加入展示流程。
18. 如果判斷錯誤，我可以手動進行更正。
19. 這個系統的回覆應該依照情緒調整語氣。
20. 感謝你協助我們完成今天的測試。

情緒訓練另外蒐集每類至少 10 段。每段應保留同一段文字的正面、負面、平靜說法，以減少「內容不同」被誤當成情緒差異的機率。

## 評估指標

| 模組 | 展示指標 | 測試資料 |
|---|---|---|
| 身分 | 四人辨識 Accuracy、未知使用者誤認率、混淆矩陣 | 每人保留錄音＋組員以外朋友錄音 |
| 情緒 | Accuracy、Macro F1、混淆矩陣 | 每類保留錄音；報告同一位說話者限制 |
| 轉寫 | CER、每段原始與校正文字 | 使用者人工校正的中文錄音 |
| 整合 | 從錄音到顯示結果的總時間 | 現場示範實際錄音 |

## 錯誤處理與限制

- 音檔太短、靜音、損壞或無法解碼時，不加入訓練，但在分析紀錄中留下失敗原因。
- 模型未訓練時，介面明確告知需先加入對應資料，不產生猜測結果。
- 未知門檻尚未校準前，身分介面顯示「暫用門檻」與校準提醒，報告不可宣稱陌生人辨識已驗證。
- 小型、同校園錄音資料只能驗證本專題 Demo，不能宣稱可泛化到所有人、所有環境。
- Ollama 回覆依賴本機服務與已下載的模型；語音辨識各模組即使 Ollama 停止仍可獨立分析。

## 驗收條件

1. 在同一頁可錄音或批次上傳，並立刻自動保存原始檔。
2. 四位成員均可建立和更新聲紋範本，分析時顯示四人分數與未知使用者結果。
3. 情緒功能保留現有正面、負面、平靜訓練、分析、更正與撤回功能。
4. 中文逐字稿可顯示、校正、保存原文與正確文字，並輸出 CER。
5. 全部資料、模型、分析紀錄都保留在 `~/Desktop/專題研究`。
6. Ollama 可收到整合資料，產生中文文字回覆。
7. 介面維持 macOS 深淺色模式與本機使用方式。
