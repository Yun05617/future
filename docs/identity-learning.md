# 更新聲紋並重新訓練

後台的「更新聲紋並重新訓練」現在會重新擷取已登錄錄音的 ECAPA-TDNN 特徵，更新平均範本，並以各成員的標籤重新訓練 LogisticRegression 身分分類器。重新更正說話者及刪除上一批錄音時，也走相同更新流程。

這是真正重新擬合個人身分分類層的權重，不是微調 ECAPA-TDNN 底層網路，也不會重新訓練 Gemma 或情緒模型。使用現有 scikit-learn 套件，不下載新模型。

## 資料條件

至少兩位成員，各有兩段內容不完全相同的錄音檔，才訓練分類器。按檔案 SHA-256 去除同一成員的完全重複檔案；不同變調副本仍屬不同內容，不代表是獨立的新錄音。類別採 balanced 權重，減少樣本數差異對訓練的直接影響，但不能彌補資料缺少。

少於兩個獨特音檔的成員不參與分類器訓練。有一段者仍可保存聲紋範本，但在目前的純分類器模式下無法成為輸出身分。沒有可用的分類器時，回傳未知使用者，不會改用平均聲紋猜測身分。

## 目前展示與後台的決策規則（2026-11-06）

依使用者要求，兩個介面共用的 _LocalIdentity 採 classifier_only：選分類器支持度最高的已訓練成員，最高支持度達到 0.80（含）才接受，低於 0.80 顯示未知使用者。使用未四捨五入的支持度比較。不再要求餘弦相似度大於 0.40，也不使用相似度差距，不會對資料不足成員退回範本比對。

這是封閉集合分類，陌生人的聲音也可能被分到某位已訓練成員；高支持度不是實際正確率或可靠的未知者拒絕能力。底層 ECAPA-TDNN 仍負責提取聲紋，並未移除。底層 identify_speaker 保留預設 hybrid 模式作舊版對照，介面已明確指定 classifier_only。

## 分數與紀錄

分析 JSON 的 `scores` 仍是每人的原始餘弦相似度，僅供紀錄，沒有改成支持度。`classifier_scores` 為各類別未校準的相對支持度，不是準確率。`support_threshold` 保存本次採用的支持度門檻，低於門檻時仍保留各候選支持度供檢查。新介面紀錄的 `decision_method` 為 classifier_only，尚無分類器時為 classifier_unavailable。`model_version` 記錄使用的訓練版本。

訓練紀錄包含各人成員錄音數、去重後數量、參與類別、時間及版本。沒有把訓練集上的成績當測試準確率。需另外建立未參與建檔、且不與擴增檔同源的真實測試集，包含其他成員及未知者。

## 更新安全

所有新範本、分類器係數及訓練摘要整合在資料庫 `03_語音身分辨識/learned_identity.npz`，不使用 pickle，全部完成後才原子替換。既有 npy 範本保留作舊版相容，更新後新版辨識以 npz 為準。再次更新前自動將前一份 npz 保存在「模型更新備份」。訓練失敗不發布部分結果，辨識可繼續讀取前一份模型。

同一資料庫使用排他更新鎖；若程式被強制終止，確認沒有訓練程序後才能手動移除 `identity-update.lock`。新模型首次需要重新啟動原本後台與展示程式才會載入新程式碼。後續同一程式內更新不需重新啟動。
