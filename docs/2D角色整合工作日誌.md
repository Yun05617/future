## 2026-11-16 第二次修改：自動語音回覆

使用者實機確認訊息能正常回覆，但 macOS 沒有語音。原因是原本 `reply_speech.py` 只有 Windows 語音介接，在 macOS 會直接回報不支援。

本次已完成：

1. 新增 macOS 本機語音支援，使用系統內建 `say` 產生台灣中文語音，再以 FFmpeg 轉為網頁可播放的單聲道 24 kHz WAV；文字不會送往外部服務。
2. 訊息回覆完成後自動合成並播放語音，不再需要先按播放按鈕；按鈕改為「重新播放語音」供需要時重播。
3. 回覆音訊播放事件會把角色切換為說話狀態，Web Audio 音量分析持續控制嘴型透明度，播放結束後回復待機。
4. 移除角色下方的風格、身世及「準備回覆」等描述，只保留辨識出的姓名。
5. 以真實 macOS 語音引擎產生 3.75 秒 WAV，確認格式為單聲道、24 kHz。
6. 實際送出文字後，已確認自動產生 1.18 秒回覆語音並完成播放。另修正 Gradio 同時建立標準播放器與波形播放器時，只綁到隱藏播放器、導致人物不動的問題。角色動畫現在直接使用合成 WAV 的實際秒數啟停，不受 Gradio 內部播放器結構影響；實機驗證播放中人物狀態為 `speaking`、嘴型透明度約 0.50。
7. 全專案測試更新為 170 項通過、2 項依平台略過，沒有失敗。

Safari 若阻擋第一次自動播放，先在頁面任意點一下，再送出下一則訊息；同一次瀏覽期間通常不會再次阻擋。

## 目標

將五位既有角色整合到 `future-main` 的競賽展示前台，讓角色能依語音辨識出的使用者自動切換，並在回覆音訊播放時對嘴、平時自然眨眼。此階段採免費、完全在瀏覽器本機執行的 2D 圖層方案，不依賴付費 API。

## 穿模問題與處理方式

先前嘴巴與眼睛看起來像穿模，是因為不同狀態圖的整張臉直接切換或疊加時，邊緣和位置差異會同時被看見。本次改為三層固定座標：底圖永遠顯示，說話圖只隨音量短暫增加透明度，眨眼圖只顯示 145 毫秒，而且說話時暫停眨眼。所有圖層共用相同容器、尺寸、底部對齊與裁切規則。

注意：目前素材仍是三張「完整人物圖」疊加。如果來源圖片的頭部或身體位置本身不完全一致，高音量時仍可能有極輕微雙影。最精準的下一步是把嘴與眼睛各自裁成只含局部的透明圖層，或改用 Live2D 網格變形；這不影響目前功能使用。
